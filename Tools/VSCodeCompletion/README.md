# Local Completion for Visual Studio 2022

Ollamaのローカルモデルを使う、C++用のコード補完拡張機能です。APIキー・有料APIは使いません。

## インストール

1. 編集中のファイルを保存し、Visual Studio 2022を終了します。
2. このフォルダーの **`Setup.cmd` をダブルクリック**します。
3. Ollamaがなければインストールし、`qwen2.5-coder:1.5b-base`（約1GB）をダウンロードします。初回はネット接続が必要です。
4. モデルの生成テストのあとに表示されるVSIXインストーラーで、拡張機能をインストールします。
5. Visual Studio 2022を起動し、C++のソースまたはヘッダーを開きます。

Ollamaとモデルが導入済みなら、`artifacts/LocalCompletion.vsix` をダブルクリックして拡張機能だけをインストールすることもできます。VS2022 17.14以降の64ビット版が対象です。VS2026は対象外です。

署名のない自作拡張機能なので、インストーラーに発行元の警告が表示される場合があります。ソースはこのフォルダーにあります。

## 操作

| 操作 | 結果 |
|---|---|
| C++の行末で入力後、約0.8秒待つ | 1行分の候補を薄い文字で表示 |
| `Ctrl + Alt + Enter` | 手動で補完を要求 |
| `Tab` | 表示中の候補を挿入 |
| `Esc` | 候補・生成待ちを取り消す |
| `Ctrl + Z` | 採用した補完を元に戻す |
| ツール → Local Completion: 自動補完を切り替え | 自動補完をオン／オフ |
| ツール → Local Completion: 接続テスト | Ollamaに短いコードを生成させて確認 |

動作確認には、C++ファイルに次のように入力し、`return` の直後で手動補完します。

```cpp
int Add(int a, int b)
{
    return
}
```

IntelliSenseの候補一覧が開いている場合は、先にEscで閉じます。既存のIntelliSenseのTab操作を優先するため、その間はこの拡張機能の補完を行いません。

ショートカットが別機能と競合したら、ツールメニューから実行するか、ツール → オプション → 環境 → キーボードで `LocalCompletion.Complete` の割り当てを変更します。

## 設定

ツール → オプション → **Local Completion → 全般** にあります。

- 接続先: `http://localhost:11434`。このPC内のHTTPアドレスのみ使えます。
- モデル: 初期値は `qwen2.5-coder:1.5b-base`。Qwen2.5 CoderのFIM形式で生成するため、同系列の **baseモデル** を使ってください。
- 入力待ち時間: 初期値800ミリ秒。
- タイムアウト: 初期値45秒。初回の読み込みが遅い場合は増やしてください。
- 文脈: 初期値はカーソル前6000文字・後2000文字。同じファイルだけを参照します。

設定は `%LOCALAPPDATA%\LocalCompletion\settings.xml` に保存します。生成したコードや送信した文脈は拡張機能ではログに残しません。ローカルのモデルへ送るコードは、開いているファイルのカーソル周辺だけです。

RTX 4060 Ti 8GBでは、まず初期モデルで速度と精度を確認してください。より大きい同系列のモデルに変更するときは、事前に `ollama pull モデル名` を実行します。ゲーム実行中に重くなる場合は自動補完をオフにします。モデルは最後の要求から約2分で解放する設定です。すぐに解放するには `ollama stop qwen2.5-coder:1.5b-base` を実行します。

## 初版の範囲

- **行末での1行補完**です。行の途中の補完、複数行の一括生成、次の編集箇所の提案は含みません。
- C++エディターが対象です。他言語や差分／投影ビューのサポートは含みません。
- プロジェクト全体の索引は作成しません。別ファイルのクラス定義などは自動では参照しません。
- AIの生成なので、常に候補が出るとは限らず、コンパイルできることも保証されません。
- Copilotなど別のインライン補完拡張機能と同時に使う場合は、片方の自動補完をオフにしてください。

## 問題が起きた場合

- **接続できない**: スタートメニューからOllamaを起動し、接続テストを実行します。
- **モデルがない**: `Setup.cmd` を再実行するか、`ollama pull qwen2.5-coder:1.5b-base` を実行します。
- **候補が出ない**: C++の行末にカーソルがあるか確認し、IntelliSenseを閉じて手動補完します。接続エラーなどはVSのステータスバーに表示します。エラー後は自動要求を15～30秒休止します。
- **VS2022にメニューがない**: VS2026を開いていないか、拡張機能の管理でLocal Completionが有効か確認してVS2022を再起動します。
- **wingetがない**: [Ollama公式サイト](https://ollama.com/download/windows)からOllamaをインストールしたあと、`Setup.cmd`を再実行します。

アンインストールはVS2022の「拡張機能の管理」から行えます。モデルの削除は `ollama rm qwen2.5-coder:1.5b-base`、Ollama本体の削除はWindowsの「インストールされているアプリ」から行います。

## 開発・検証

`Build.ps1` はVisual Studio 2022のMSBuildとNuGetのVS SDKを使い、`artifacts/LocalCompletion.vsix` を作成します。開発者は.NET SDKも必要です。ゲームのプロジェクトとは独立しています。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
dotnet run --project Tests/Tests.csproj -c Release
```

テストではローカルHTTPサーバーを使い、FIM形式、日本語の文脈、応答解析、モデル未導入、キャンセル、タイムアウト、処理復帰、古い応答の判定を検証します。VSの画面上の表示・キー操作の検証は別途必要です。

使用技術: Visual Studio SDK / MEF / WPF、Ollama `/api/generate`、Qwen2.5 CoderのFIM。
